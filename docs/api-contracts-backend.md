# API Contracts - Backend

**Date:** 2026-07-24
**Source:** `backend/api/router.py`

## Overview

The backend currently exposes a single `APIRouter` (no prefix, no sub-routers, no versioning) with exactly one endpoint. All routes are `async def` and use explicit Pydantic `response_model`s per project convention — no route returns a bare dict.

## Authentication

**None.** No authentication or authorization middleware/dependency exists anywhere in the codebase. Every endpoint below (and any added in the future, until an auth layer is built) is effectively public.

## Base URL

- Local dev: `http://localhost:8000`
- Docker Compose (frontend build-time default): `http://localhost:8000`
- Interactive docs (Swagger UI, auto-generated by FastAPI): `http://localhost:8000/docs`

## Endpoints

### `GET /health`

Health check endpoint.

- **File:** `backend/api/router.py`
- **Auth required:** No
- **Request:** none (no path/query/body parameters)
- **Response model:** `HealthResponse`

```json
{
  "status": "ok"
}
```

**Response schema:**

| Field | Type | Description |
|---|---|---|
| `status` | string | Always `"ok"` when the process is responsive; no dependency checks (DB connectivity, etc.) are performed |

## Not Yet Implemented

Based on the modeled data ([data-models-backend.md](./data-models-backend.md)), no endpoints exist yet for any of the system's core domains:

- User management / authentication (login, user CRUD, role checks)
- Menu management (categories, dishes)
- Recipes & ingredients
- Table & order management (order lifecycle, order items)
- Inventory (stock movements, low-stock alerts)
- AI features (recipe suggestions, chat sessions)

When these are added, follow the project convention: a dedicated `APIRouter` per domain, included into `backend/api/router.py`'s main router, rather than growing a single file.
