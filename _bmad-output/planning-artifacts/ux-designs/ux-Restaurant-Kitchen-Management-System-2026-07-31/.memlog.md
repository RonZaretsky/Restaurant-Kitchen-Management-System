- (decision) Form-factor resolved: single-surface responsive web, desktop/PC browser only for all 4 roles (Waiter, Cook, Warehouse Manager, Admin) -- no native mobile/tablet, no separate physical controller for the kitchen display. Simplifies IA closure considerably.
- (decision) Theming: system supports both light and dark mode as a real toggle (not per-role hardcoded) -- every screen is theme-aware. Cook's kitchen display defaults to dark (glare/distance-legibility reasoning still applies as the default, not a hard rule); other roles default to light. All switchable.
- (decision) Tone confirmed: fast and stripped-down -- no restaurant branding, no marketing copy, every screen optimized for shift-speed. Matches the internal-tool stakes call.
- (decision) New IA surface confirmed via party-mode debate: Cook gets a read-only Dishes view (catalog + recipe/plating context while cooking). Explicitly no create/modify rights for Cook -- matches the current PRD design, where dish creation/edit is Admin-only (FR-22) even for Cook-originated Smart Chef suggestions (FR-19's confirmation gate). No PRD/architecture change needed since this stays within existing role boundaries.
- (decision) Cook-requests-new-ingredient feature explicitly skipped for v1 -- confirmed out of scope by Ofek. No request/approval path for a Cook to get a new Ingredient added; ingredient creation stays Warehouse-Manager/Admin-only (FR-16), unchanged from current PRD.
- (decision) Information Architecture confirmed: 13 surfaces across 4 roles (Login; Waiter: Tables, Table/Order detail; Cook: Kitchen Display, Dishes view-only, Smart Chef; Warehouse Manager: Ingredients, Ingredient detail, Alerts; Admin: Menu Management, Recipe Suggestions, Users, Tables setup). No objections raised -- locked.
- (decision) Visual accent: cool blue/teal layered on top of MUI defaults -- not pure-stock MUI, not a warm/kitchen-themed accent. Reads as clean back-office software.
- (decision) Status color convention: traffic-light (red/amber/green family) for OrderItem/Order status everywhere it appears, PAIRED with a distinct icon and/or label per status -- never color-only, to stay legible for colorblind users on the kitchen display specifically.

A persistent counter (mirrors Noa's Alerts badge pattern) shows how many tables currently need attention, visible from the Table detail screen too, not just the grid. Clears automatically once she marks the order served (FR-11), no separate dismiss action needed.
